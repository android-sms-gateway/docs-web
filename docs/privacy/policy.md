# Privacy Policy 🔒

We are committed to transparency and the protection of user privacy. This document outlines how we handle information within our app.

## Data Handling :material-database:

=== ":material-server: Local Server"
    !!! info "Public IP Retrieval"
        - 🌐 Public IP obtained via Cloud/Private server
        - 📦 Request includes:
            - App version 
            - Server token (if applicable)

=== ":material-cloud: Cloud Server"
    !!! info "Encryption"
        1. All communication between the app and the cloud server is protected with secure encryption protocols, safeguarding your data during transit.
        2. [End-to-end encryption](./encryption.md) optional but recommended:
            - 🔑 Messages data is encrypted before being sent to the API 
            - 📨 Decrypted only on the device
            - 👁️ No third-party access (including us)

    !!! info "Data Handling"
        - 🕒 Plaintext data hashed (SHA256) within 1 minute after processing
        - 📤 Shared data:
            - Device manufacturer and model — set as the device name at registration
            - App version — sent in the `User-Agent` header of every request (kept in request logs)
            - Firebase Cloud Messaging (FCM) token
            - SIM details — phone number, carrier and ICCID are redacted on the device (only the last 4 characters are kept)

=== ":material-home: Private Server"
    !!! info "Push Notifications"
        - 📲 Routed through cloud server
        - 🔒 Contains only FCM token
        - 🚫 No message content/recipients

=== ":material-certificate: Certificate Authority"
    !!! info "Data Handling"
        - 📝 Certificate requests are purged after 24h
        - 🔑 Private keys generated client-side
        - 📜 CSR generated by the CLI tool contains only IP address

## Data Location & Sub-Processors :material-earth:

The public Cloud Server (`api.sms-gate.app`) runs on infrastructure operated by **Timeweb Cloud** in the **Russian Federation**, together with its primary MariaDB database. A second server in **Germany (EU)**, operated by Senko Digital, holds a database replica, a cold backup of the backend and additional services. Daily database backups are stored in **Yandex Cloud Object Storage** (Russian Federation) and deleted after **12 days**.

| Sub-processor                     | Purpose                                                                                             |
| --------------------------------- | --------------------------------------------------------------------------------------------------- |
| Google (Firebase Cloud Messaging) | Wake-up push notifications — event type, message ID and date range, never message content or recipients |
| Cloudflare                        | Reverse proxy, CDN, DNS and TLS termination in front of the API                                     |
| Senko Digital                     | Hosting of the second server in Germany (EU): database replica, cold backup and additional services |
| Timeweb Cloud                     | Hosting of application and database servers (Russian Federation)                                    |
| Yandex Cloud                      | Object storage for database backups (Russian Federation, kept 12 days)                              |
